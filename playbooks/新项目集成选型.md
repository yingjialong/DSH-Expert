# 剧本：新项目集成选型

> **方法层**。这里写的是"怎么做判断"，不是"DSH 是什么"。事实随上游变，方法不变。
>
> 触发场景：有人带着一个项目来问"我想把 DSH 集成进来，怎么搞"。

## 第一原则：不要立刻回答"用哪个 SDK"

集成路径是**结论**，不是起点。先把条件问清楚，否则给出的答案换个项目就废。但**也不要把八个维度全问一遍**——只在"不同答案会导致不同路径"时才追问。

## 八维坐标（知识的索引，也是提问的清单）

| # | 维度 | 为什么它会改变结论 | 典型取值 |
| --- | --- | --- | --- |
| 1 | **宿主语言与运行时** | 决定有无官方 SDK，还是只能走协议层 | TypeScript / Python / Go / Java / Rust / 其他 |
| 2 | **运行形态** | 决定 runtime 进程的生命周期与持有方式 | CLI 一次性 / 长驻服务 / 桌面应用 / CI 任务 / Serverless |
| 3 | **并发与会话隔离** | 决定"一个 runtime 进程 vs 每请求一个"，这是长驻服务的第一大坑 | 单用户单会话 / 多用户多会话 / 需要会话恢复 |
| 4 | **沙箱与文件系统** | 决定是否需要沙箱后端、工作目录如何隔离 | 需要隔离 / 信任宿主环境 / 无文件访问 |
| 5 | **工具复用** | 决定是"用 DSH 自带工具"还是"把宿主已有能力注册成 DSH 工具" | 纯自带 / 混合 / 主要用宿主工具 |
| 6 | **模型与凭据** | 决定 LLM provider 适配与凭据注入方式，且直接关系到花钱 | 官方 DeepSeek / 自建网关 / 多 provider / 离线 |
| 7 | **部署环境** | 决定能否拉子进程、能否联网、能否装 node | 本机 / 容器 / 无外网 / 受限运行时 |
| 8 | **版本基线** | 决定给出的接口在对方那边到底存不存在 | 0.1.1-rc.2 / 0.1.0-rc.x / master / 待定 |

**提问纪律**：先按对方已给的信息推断，能推出的不问。只问那些"不同答案会导出不同路径"的维度。

## 决策流程

```
1. 定维度 1（宿主语言）
   ├─ TypeScript/Node  → 优先考虑进程内或 packages/sdk
   ├─ Python           → 优先考虑官方 Python SDK
   └─ 其他语言         → 只能走协议层（JSON-RPC / ACP / HTTP），跳到步骤 3

2. 定维度 2+3（运行形态 + 并发）
   ├─ CLI 一次性       → 进程生命周期简单，按最小路径来
   ├─ 长驻服务         → 必须先解决：runtime 进程复用策略、会话隔离边界、异常回收
   └─ Serverless       → 冷启动开销与子进程可行性是硬约束，先验证能不能拉进程

3. 查 wiki/integration/integration-surfaces.md 拿到当前可用的集成方式全表
   （不要凭记忆列举，方式与稳定性标注会随版本变）

4. 用维度 4-7 排除不可行的方式
   例：无外网 → 排除需要拉远端 runtime 的方式；受限运行时不能拉子进程 → 排除子进程型 SDK

5. 定维度 8（版本基线），把结论钉死在具体版本上
   → 明确告知：此结论基于哪个版本，升级到 master 有什么已知差异
```

## 回答必须包含的四件事

1. **推荐路径 + 一句话理由**
2. **该路径的已知代价**（不能只说好处：进程开销、隔离粒度、协议实现工作量、稳定性标注）
3. **被排除的路径与排除理由**（对方可能已经在考虑其中之一）
4. **版本基线声明**（"基于 0.1.1-rc.2；master 上 X 已改动"）

## 沉淀规则（双门槛）

回答完必须回写知识库，先过主题门槛、再谈通用性——**只写坐标格子中结论落在 DSH 行为上的条目**（`CLAUDE.md` 第 7 条）：

```
✅ 条件：宿主为长驻服务 + 多用户多会话 → 结论：（DSH 侧结论）→ 锚点：… → 状态：verified_inference
❌ XX 项目用 FastAPI，要在 startup 里拉进程          ← 换个项目就废，禁止写入
❌ 长驻服务的通用进程管理做法（与 DSH 无关的结论）  ← 哪怕完全去项目化，同样禁止写入
```

写入 `wiki/integration/`，按维度组合命名。**第二次遇到同一格子就直接命中，这就是"越问越聪明"的落点。**

## 失败的方法（别再走一遍）

| 走过的死路 | 为什么错 |
| --- | --- |
| 一上来就推荐"用 Python SDK" | 只对 Python 宿主成立；对方是 Go 时完全跑偏 |
| 从 README 的 Quick Start 直接推导集成方案 | Quick Start 讲的是**独立使用**（`npx dsh web`），不是**被集成** |
| 假设 API 稳定 | developer preview，rc.7→rc.8 两天变了 1604 个文件 |
| 只看 packages 的 README 表格判断可用性 | 表格会漏组（见 errors.md E002），以 `ls packages/` 为准 |
