# 0.1.1-rc.2 → 0.1.2-alpha.1 版本变更摘要

> 区间：`b150a551`（`dsh-v0.1.1-rc.2`）→ `cd5ef814`（`dsh-v0.1.2-alpha.1`），1079 个提交、6421 个文件（+323745 / −126827）。查询于 2026-08-28：npm `@deepseek-ai/dsh` 的 `latest` / `next` 仍为 `0.1.1-rc.2`，PyPI `deepseek-harness-sdk` 仍为 `0.1.1rc1`。因此 alpha.1 是当前仓库 tag/HEAD，不是 npm 已发布基线。

2026-08-30复验：GitHub release `v0.1.2-alpha.1` 是官方prerelease但无binary/npm附件；source tarball/zipball指向同一tag。对tag中239个非private `@deepseek-ai/dsh-*` package name逐一查npm，`0.1.2-alpha.1`命中0；PyPI SDK/runtime也没有alpha.1。因此不存在可供第三方安装的alpha.1正式package闭包。

## 已验证的主要破坏性变更

1. **Host API 拆成 domain controllers。** `packages/host/apiproxy` 被删除，Session、Workspace 和 Settings/Credentials 转入 `packages/api/{session-controller,workspace-controller,settings-controller}`。依赖 rc.2 `createApiProxy` / `ApiProxy` / `host-apiproxy` wire 面的嵌入宿主不能把 alpha.1 当作小版本更新。
2. **Client Runtime owner 重组。** `packages/client/runtime` 被删除；Session/Workspace client owner 迁入对应 controller，通用状态存储拆为 `packages/client/store`。rc.2 的 `SessionRuntime` / `Workspaces` 组合与导入面需重审。
3. **Remote 载体转向 generation-aware stream。** API Gateway 新增多路 stream protocol、snapshot/journal stream 与物理 generation 换代，旧 apiproxy 的 unary/event 所有权被重分配。
4. **类型词汇重命名。** `CallId` 重命名为 `ToolCallId`；产品文案中 Code Mode 改称 PTC（持久 Session 词汇例外）。直接引用老类型名的插件需迁移。
5. **外部Session event更严格。** rc.2 persistence允许白名单外事件在envelope带`ignorable:true`时读取；alpha.1的`KNOWN_SESSION_EVENT_TYPES`说明out-of-repo registration仍deferred，coordinator改为未知event一律拒绝。仅做TypeScript declaration merge不能再让第三方required event跨重启恢复。

## 与本次集成审计直接相关的未改变边界

- Workspace archive 在 alpha.1 仍是单向操作；官方 README 明确写明尚无 unarchive，也没有 Session deletion 产品面。
- `@deepseek-ai/dsh-mcp-client` 仍只在根导出闭合的 stdio / Streamable HTTP 配置与 plugin `apply`；内部 `createTransport` / connection supervisor / tool-generation 未变成可注入 carrier 的 npm 公共面。
- reasoning effort 仍由 exact adapter/model metadata 持有；core 没有通用 `high` 默认。
- `dsh-mcp-client`在tag中改成registration-scope namespace，可被不同Agent scope复用serverName；transport仍内部硬建，无公开carrier factory或generation snapshot。

## alpha.1 宿主形态专项结论

- 完整产品图来自source-built `dsh --profile`或Node内`app-boot`+Loader装配，不来自SDK/ACP wire。
- Web Remote/controller/client-store是完整一方控制面；`dsh-client-connection/client`公开`ClientTransportHooks`，允许shell提供fetch/openStream/loadBundle/ownsHost来承载IPC/postMessage。非React TS可复用；非TS没有完整稳定协议。
- SDK保持3请求+4通知；ACP虽扩展持久Session、model/MCP/permission/cancel，仍明确排除history/fork/Workspace/settings与DSH-specific UI。
- 完整说明见[`integration/alpha1-full-host-embedding.md`](../integration/alpha1-full-host-embedding.md)。

## 对集成方的影响

| 集成方依赖 | 影响 |
| --- | --- |
| rc.2 `host-apiproxy` / `client-runtime` 公共面 | 拓扑重写，不是仅升包版本 |
| 自定义 Main/Renderer carrier | 需重新对齐 Gateway Remote/controller generation 语义 |
| 自定义 Session/Workspace UI | 需改用 controller-owned client 服务与 store |
| 仅锁定 npm rc.2 的产品 | 应继续以 `b150a551` 为事实基线，不得引用 alpha HEAD 类型作为当前公开 seam |

## 升级建议

1. 先把 alpha.1 当作新的 Host/Client 拓扑迁移，单独盘点 `host-apiproxy`、`client-runtime`、旧 event carrier 和类型导入。
2. 迁移时以 Session/Workspace/Settings controller 的公开 package exports 和官方测试为新契约，不从删除包的旧实现反推。
3. npm 未发布 alpha.1 前，生产依赖不应混用仓库 HEAD 与 rc.2 tarball。
