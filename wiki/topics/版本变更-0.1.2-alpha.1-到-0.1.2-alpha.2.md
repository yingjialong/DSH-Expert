# 0.1.2-alpha.1 → 0.1.2-alpha.2 版本变更摘要

> 区间：`cd5ef814`→`0a53fb55`，234提交、1604文件、+27862/−14050。GitHub于2026-08-30T13:52Z发布alpha.2 prerelease；npm根包于14:10Z发布到`alpha`，`latest`/`next`仍为rc.2，PyPI SDK仍`0.1.1rc1`。发布状态在本轮查询中发生变化，以下使用最终快照。

## 官方release明确列出的变化

- Web显示connection failure、automatic retry与立即重连；conversation header显示active schedules。
- plugin inventory按conversation/global scope分组，可切换AgentPreset并跨preset搜索。
- 长history与密集live messages性能优化；answer tail显示token/耗时；菜单、滚动、tool file link、diff统计与权限本地化调整。
- 修复Node 24.0–24.11.1启动/HMR问题，减少macOS/Linux冷Session不必要filesystem检查。
- 恢复alpha.1移除的`SessionEvent.ignorable`；Remote gateway统一`RemoteError`。
- 依赖owner重组以缩减不必要peer dependencies；vendor发布到Cordis 4.0.2、Loader 1.0.3、Include 1.0.7等。

## 源码/闭包形状

- `KNOWN_SESSION_EVENT_TYPES`继续是build-time仓内词汇表；alpha.2恢复unknown `ignorable:true`兼容路径，不等于新增out-of-tree required vocabulary runtime registration。
- alpha.1的controller/client-store大拓扑仍在；本页未发现ApiProxy/client-runtime回归。

## Skill、Session correlation 与 MCP 专项公共面

- **没有per-Session exact Skill/MCP active-set vocabulary**：alpha.2的`KNOWN_SESSION_EVENT_TYPES`没有Skill/MCP selection事件；Session controller新增的`skills.list({sessionId})`只返回当前composition可见的user-invocable Skill目录，不含selected refs、digest、revision或durable active-set projection。ACP可在未发布Agent scope挂载一次请求给出的MCP rows，但这也不是Session耐久refs。
- **Skill observation仍无公开lease/CAS**：正式`SkillCatalogSnapshot`只有`skills`与`complete`；`SkillRegistry.revision`仍为private，`skills/change`仍是无payload invalidation。没有把Skill collect/definition validation与Session append组成原子validate-and-append的公共seam。
- **prompt只新增correlation identity**：`SessionPromptRequest.requestId`由Client生成并写入accepted user message的`source.rpcId`，供optimistic echo对账；Host没有按该ID去重，也没有commit-status query。它不是幂等提交协议。
- **MCP仍非2026-07-28 modern-only**：正式`dsh-mcp-client`根Config仍固定stdio或Streamable HTTP，根不导出carrier/factory或generation identity。tag lock解析`@modelcontextprotocol/sdk`为1.29.0；其正式tarball声明latest protocol为`2025-11-25`，supported list不含`2026-07-28`。内部connection/tool generation guard与全量swap不能提升为Host/Session公共generation contract。

### 2026-08-31正式tarball逐项复核

- **Skill catalog identity仍缺**：正式`dsh-skill` root `.d.ts`中`SkillCatalogSnapshot`仍只有`skills/complete`；private `revision`与无参`skills/change`不构成public generation/lease/CAS。`SkillSummary`只公开winner的`source/provider/resourceBase`，没有shadowed candidates/provenance chain或exclude provider/layer view；Session Remote的`SkillEntry`连winner provider/source都不出wire。
- **definition仍是borrowed string**：`SkillProvider.get()`返回`SkillDefinition{content:string,path?,metadata?,resourceBase?}`；`locator:unknown`只在同一provider往返。没有authenticated immutable bytes/fd/blob、digest/signature、revision或load receipt resolver。
- **Skill与Session没有共同提交**：没有把snapshot/definition load/collision validation与Session durable append绑在同一operation的export/type/runtime/test；`complete`只是单次collect状态。
- **Preset仍无first-prompt barrier/append rollback**：`AgentPresets.select()`只用private`switches`串行同Session多个select并在队内重读`turnBoundary`；`SessionController.prompt()`独立`agent.followup/steer`。`recompose()`先rebind并emit，`swap()`随后单独append`agent-preset/selected`，没有append失败后的反向rebind或相关一方test。
- **MCP没有raw inspector或public generation**：根仍只导出`Config/apply/inject/name`与结果/重连types；直接构造两类transport。通用`tools/post-execute`可在durable`tool/result`前看映射后的`McpResult`，但没有raw HTTP/protocol response inspector。内部definition closure捕获当代SDK Client，工具swap是generation-safe；generation id不进入public ToolExecution/result/snapshot/log。
