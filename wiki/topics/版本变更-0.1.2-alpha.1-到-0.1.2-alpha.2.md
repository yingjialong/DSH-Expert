# 0.1.2-alpha.1 → 0.1.2-alpha.2 版本变更摘要

> 区间：`cd5ef814`→`0a53fb55`，234提交、1604文件、+27862/−14050。GitHub于2026-08-30T13:52Z发布alpha.2 prerelease；npm根包于14:10Z发布到`alpha`，`latest`/`next`仍为rc.2，PyPI SDK仍`0.1.1rc1`。发布状态在本轮查询中发生变化，以下使用最终快照。

## 官方release明确列出的变化

- Web显示connection failure、automatic retry与立即重连；conversation header显示active schedules。
- plugin inventory按conversation/global scope分组，可切换AgentPreset并跨preset搜索。
- 长history与密集live messages性能优化；answer tail显示token/耗时；菜单、滚动、tool file link、diff统计与权限本地化调整。
- 修复Node 24.0–24.11.1启动/HMR问题，减少macOS/Linux冷Session不必要filesystem检查。
- 恢复alpha.1移除的`SessionEvent.ignorable`；Remote gateway统一`RemoteError`。
- 依赖owner重组以缩减不必要peer dependencies；vendor发布到Cordis 4.0.2、Loader 1.0.3、Include 1.0.7等。

## 源码/闭包形状

## Skill、Session correlation 与 MCP 专项公共面

- **没有per-Session exact Skill/MCP active-set vocabulary**：alpha.2的`KNOWN_SESSION_EVENT_TYPES`没有Skill/MCP selection事件；Session controller新增的`skills.list({sessionId})`只返回当前composition可见的user-invocable Skill目录，不含selected refs、digest、revision或durable active-set projection。ACP可在未发布Agent scope挂载一次请求给出的MCP rows，但这也不是Session耐久refs。
- **Skill observation仍无公开lease/CAS**：正式`SkillCatalogSnapshot`只有`skills`与`complete`；`SkillRegistry.revision`仍为private，`skills/change`仍是无payload invalidation。没有把Skill collect/definition validation与Session append组成原子validate-and-append的公共seam。
- **prompt只新增correlation identity**：`SessionPromptRequest.requestId`由Client生成并写入accepted user message的`source.rpcId`，供optimistic echo对账；Host没有按该ID去重，也没有commit-status query。它不是幂等提交协议。
- **MCP仍非2026-07-28 modern-only**：正式`dsh-mcp-client`根Config仍固定stdio或Streamable HTTP，根不导出carrier/factory或generation identity。tag lock解析`@modelcontextprotocol/sdk`为1.29.0；其正式tarball声明latest protocol为`2025-11-25`，supported list不含`2026-07-28`。内部connection/tool generation guard与全量swap不能提升为Host/Session公共generation contract。

### 2026-08-31正式tarball逐项复核

- **Skill catalog identity仍缺**：正式`dsh-skill` root `.d.ts`中`SkillCatalogSnapshot`仍只有`skills/complete`；private `revision`与无参`skills/change`不构成public generation/lease/CAS。`SkillSummary`只公开winner的`source/provider/resourceBase`，没有shadowed candidates/provenance chain或exclude provider/layer view；Session Remote的`SkillEntry`连winner provider/source都不出wire。
- **definition仍是borrowed string**：`SkillProvider.get()`返回`SkillDefinition{content:string,path?,metadata?,resourceBase?}`；`locator:unknown`只在同一provider往返。没有authenticated immutable bytes/fd/blob、digest/signature、revision或load receipt resolver。
- **Skill与Session没有共同提交**：没有把snapshot/definition load/collision validation与Session durable append绑在同一operation的export/type/runtime/test；`complete`只是单次collect状态。
- **Preset仍无first-prompt barrier/append rollback**：`AgentPresets.select()`只用private`switches`串行同Session多个select并在队内重读`turnBoundary`；`SessionController.prompt()`独立`agent.followup/steer`。`recompose()`先rebind并emit，`swap()`随后单独append`agent-preset/selected`，没有append失败后的反向rebind或相关一方test。
- **MCP没有raw inspector或public generation**：根仍只导出`Config/apply/inject/name`与结果/重连types；直接构造两类transport。通用`tools/post-execute`可在durable`tool/result`前看映射后的`McpResult`，但没有raw HTTP/protocol response inspector。内部definition closure捕获当代SDK Client，工具swap是generation-safe；generation id不进入public ToolExecution/result/snapshot/log。

### 2026-08-31 MCP subscription、relist与schema publication边界

- **两版都不是2026-07-28 client**：rc.2与alpha.2正式root exports相同，runtime都只实现legacy `initialize`、分页`tools/list`、`notifications/tools/list_changed`与`tools/call`。tag lock的SDK 1.29.0和当前无锁可解析的1.30.0都声明latest protocol为`2025-11-25`，没有`server/discover`或`subscriptions/listen`，因此不存在request-id=subscription-id语义。
- **`list_changed`只是当前Client generation的通知**：handler排入private `syncChain`，执行uncached full relist；成功整代swap，fetch失败保留last-good。stale generation handler由`isCurrent`忽略。
- **断线不立即失效last-good**：transport `onclose`清current Client并安排重连，但工具definitions继续注册；其closure持有dead Client，调用会失败。新Client连接后重新initialize+full relist再swap；耗尽`maxAttempts`才注销。`reconnect.enabled:false`会无限保留已注册但不可调用的旧工具。
- **Host dispose才是确定注销点**：停止timer、关闭Client、等待attempt/sync quiescent，再注销当前整代；迟到close/notification不再恢复。server自己graceful close仍走普通disconnect/reconnect，不等同plugin dispose。
- **没有public/durable MCP generation**：内部identity只是SDK `Client`对象与`Map<publicName,disposer>`；`serverName`是稳定namespace，不是generation。SessionEvent/projection、ToolExecution、`tool/call`/`tool/result`都不含server/tool generation或catalog snapshot/diff。
- **通用`request/header`只证明实际schema，不证明fresh**：每个step在`preStep`重新assemble当前ToolRuntime view，将工具数组写入`request/header`并freeze进model request；checkpoint plugin可在adapter前flush。MCP relist private chain不被AgentLoop等待，pending relist时step合法读取last-good；同turn后续step也会重新assemble，故没有整turngeneration pin。
- **schema与call未绑定同代**：模型响应回来后ToolRuntime按当时current registry resolve definition；MCP可在请求在途时swap。旧schema工具可能变成`UNKNOWN_TOOL`，同名也可能由新Client closure执行。内部definition捕获当代Client并不产生可观察、可恢复的generation-bound call/result contract。
- **最窄缺口是三段共同存在**：现代subscription lifecycle（含disconnect/relisten identity）+ public/durable catalog generation snapshot + 在model dispatch前提交并flush observation/schema、随后把tool resolve/call/result pin到同代的barrier。当前private syncChain、generic tool schemas与request/header不能替代。

### 2026-08-31 ToolRuntime execution generation borrow复核

- **alpha.2未新增definition-generation lease**：正式`dsh-tools`根`.d.ts`仍只有call correlation用的`ToolExecutionToken`；`ToolExecution`不携带definition/schema/registration generation，`register()`仍只返回同步disposer。`TOOL_RUNTIME_SCHEDULER`虽出现在根类型中，但明确是`@internal`且不是plugin extension point；没有borrow/retire/ref-count/release/whenIdle公共成员。
- **schema与执行仍分阶段读取current registry**：每个step的system-prompt assembly克隆当时schema并耐久写入`request/header`，但不保存definition handle。`createExecution()`只快照`finalizeContent`；classification/body dispatch、wrapper success normalization与post value replacement会在各自阶段按name重查current definition。body一旦选中definition，该次execute与首次output normalization用同一局部对象，但这不是全流水线generation pin。
- **replacement一方测试仍钉住动态行为**：alpha.2继续测试exclusive barrier替换tool后pending calls重新classification并执行replacement；tool在post value replacement或wrapper success normalization前消失时得到`UNKNOWN_TOOL`。这些行为与rc.2一致，不能解释成旧generation借用。
- **MCP内部generation没有提升为ToolRuntime lease**：`syncTools()`仍同步dispose previous registrations后注册next；definition closure捕获当代SDK Client只保护已经选中body后的局部调用。connection的private`isCurrent`/`syncChain`只串行连接与swap，dispose不追踪ToolRuntime in-flight execution。
- **条件性后果**：需要“schema G→retry/call/result G、G2 swap后保留G并在最后借用释放后dispose”的消费者，在rc.2和alpha.2都无法只用正式public contract构造等价保证；仍缺DSH-owned generation identity、assembly→execution handle传递、retire/ref-count/release与drain-before-resource-dispose。未来API与版本未知。
