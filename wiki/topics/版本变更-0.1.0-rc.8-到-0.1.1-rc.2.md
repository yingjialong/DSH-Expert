# 0.1.0-rc.8 → 0.1.1-rc.2 版本变更摘要

> 区间：`141eb6f`（dsh-v0.1.0-rc.8）→ `b150a55`（dsh-v0.1.1-rc.2），207 提交 / 2416 文件（+30503 / −12485；其中 949 个是 `.agents/notes` 开发笔记，138 个 docs 约 96% 为翻译再生成与锚点去行号）。发布节奏：0.1.1-rc.1 与 rc.2 同日（2026-08-21）先后发布；npm `latest` 与 `next` 均已指向 `0.1.1-rc.2`，PyPI SDK 落后一个 rc（`0.1.1rc1`）。
> Cordis 内核（`upstream/cordis`）本区间**零变更**。

## 一句话总评

**两个主题**：①图片管线统一（vision model + Files API + 两级限额 + 请求期投影）；②credentials 从「环境引用」长成「引用 + 持久记录 + 授权 flow」。前者主要砸**发图的宿主**，后者主要砸**写凭据插件的宿主**；projection register 改名砸**所有注册自定义 projection 的插件**。

## 破坏性变更（源码级，T1）

### B1. credentials 事件拆分 + record 半边（插件作者必改）

- 事件 `credentials/updated(ref)` **删除**，拆为 `credentials/reference-updated(ref: CredentialRef)` 与 `credentials/record-updated(key: CredentialKey)`。**监听旧事件名的代码静默失效**（无兼容层）。
- `CredentialProvider` 从 4 方法扩到 9：ref 半边 `resolve/describe/set/unset` 不变；新增 record 半边 `readRecord/describeRecord/listRecords/modifyRecord/deleteRecord`（`modifyRecord` 唯一写路径，跨进程 writer 锁下 read-decide-replace，锁等待 30 s）。
- `.credentials.yaml` 从平面 `ref: value` 变为 `version: 1` + `refs:` + `records:` 三段结构；pre-release 平面布局 boot 时在锁下自动迁移（原行逐字嵌入 `refs:`），热重载**不**迁移。
- 新类型：`CredentialKey`（`<scope>/<id>`，scope 为 owner 插件注册名）、`ApiKeyRecord`、`GrantRecord`、`CredentialRecord`。
- 主提交：`86a9f8c86`（records）、`732a7361f`（authorization）、`fecfabcac`（事件改名）。

### B2. projection register 接口重构（所有自定义 projection 必改）

- `ProjectionDefinition`：`schema` → **`stateSchema`**；`view(state)` → 可选块 **`wire: { viewSchema, view }`**。省略 `wire` 即 **host-only 单元**（checkpoint 照常，但不进 snapshot / change feed）。
- key 合并路径变化：state key 先并进新类型表 `SessionProjectionStateMap`，client-visible 的才再进 `SessionProjectionMap`。
- 覆盖范围变化：`snapshot()` 与 change feed **只含 client-visible 单元**；`checkpoint()` 仍覆盖全部注册单元。
- 新增 API：`stateOf(session, key)`；`register` 变双重载。
- 主提交：`4c421ec88` / `9127d7e8b` / `327b86d2e`。仓内全部注册点（goal / todo / plan / session-title / apiproxy 两个）已随迁。

### B3. 图片附件两级限额 + normalized 持久化 + 请求期投影

- 限额重构：源准入单边 2000 px → **8192 px**（单张 20 MiB / 64 M px / 每消息 20 张 200 MiB）；新增独立 normalization 层（长边 2048 px / 4 MiB）。**旧行为里"准入即最终尺寸"的假设失效**。
- `saveImage` 持久化的不再是原始字节，而是 **provider-independent normalized image**（EXIF orientation 应用 + 归一化缩放）；`ImageAttachmentRef` 新增 `originalDimensions`（仅当缩小才记录）。
- 新增 `readImageRequest(ref, policy, signal?)`（基类默认抛 `ATTACHMENT_PROJECTION_UNSUPPORTED`）+ 类型 `ImageRequestPolicy` / `RequestImageAttachment` / `ImageVariantId`。
- **image region reads 整体移除**（`724783b02`，retired image-region tool 一并删）。
- 配置键变化（`docs/config-catalog.md`）：`attachment-local` 新增 `normalizedImageMaxDimension` / `normalizedImageMaxBytes` / `imageCompressionConcurrency`；`llm-deepseek` 的 `maxRequestImageBytes` **拆成** `maxRequestFilesBytes` + `maxInlineRequestImageBytes`，新增 `maxImagesPerRequest` 与 Files API offload 旋钮（`imageOffloadByteQuantum` / `inlineImageOffloadByteQuantum` / `imageOffloadCountQuantum` / `filesApiTimeoutMs` / `fileExpiresAfterSeconds` / `fileRefreshMarginSeconds` / `fileQuotaCleanupBatch`）；`DeepSeekCatalogModel` 新增 `imagePixelBudget` / `imageMaxBytes` / `imageDetail`。

### B4. Web 切换模型的图片守卫移除（行为变化）

- rc.8：会话已含图片 + 目标模型不支持 image input → api-proxy 拒绝（`model-unavailable`）。0.1.1 起该检查删除（`d29855f97`）；能力检查移到**入站准入**（ACP `assertImageRoute` / `supportsAcpImagePrompts`）与 **adapter dispatch**（`LlmRuntime.adapterStream` 对 text-only 模型用 `projectImagesForTextModel()` 做确定性占位投影，不再触发 deepseek adapter 的 `UNSUPPORTED_CONTENT` 门）。

### B5. webserver frontend-static 兜底语义收紧

- 「任意 miss → index.html 200」→ **显式 index 入口点**：`distIndex` 可读时 dist root 与 configured index path 渲染 index.html，其余 dist root 内缺失/非文件目标返回**空 404**。依赖旧 SPA-fallback 行为的前端托管部署会变。
- 原始 HTML transform（`tapIndex`）降级为 escape hatch：结构化注入（`webserver/index-inject` 事件 + `collectIndexInjections()` / `renderIndex()`）优先，taps 在结构化行之后应用。**既有的 tapIndex 用户不破坏，但新需求应走注入表。**

## 对集成方的影响（八维坐标）

| 维度 | 受影响条件 | 影响 |
|---|---|---|
| 插件形态（任意宿主语言） | 插件监听 `credentials/updated` 或实现 `CredentialProvider` | **必改**（B1）：事件名、接口签名 |
| 插件形态 | 插件注册 session projection | **必改**（B2）：`schema`→`stateSchema`、`view`→`wire`，key 合并路径 |
| 宿主语言 · 沙箱 | 用 Bubblewrap 沙箱跑不可信代码的所有部署 | **尽快升级**（安全修复：`/proc/<pid>/root` 逃逸） |
| 运行形态 · Web 前端托管 | 依赖 frontend-static SPA fallback 的部署 | 行为变化（B5）：miss 从 200 变 404 |
| 模型与凭据 · 发图工作流 | 通过 Web/ACP 发图、或依赖图片限额 | 限额放宽 + 行为变化（B3/B4）；发图前无需再手动预缩放到 2000 px |
| 版本基线 · Python SDK | PyPI `deepseek-harness-sdk` | 落后一个 rc（`0.1.1rc1`），Files API 优化可能未含 |
| 部署环境 · `.credentials.yaml` | 存量 pre-release 平面布局 | boot 自动迁移（锁下、原行保留），但**热重载不迁移**——手动编辑旧布局文件后需重启 |

## 升级建议

1. **所有部署**：升到 0.1.1-rc.2（安全修复 + npm latest）。
2. **升级前 grep 三个符号**：`credentials/updated`、`schema:`（projection register 调用）、`maxRequestImageBytes`——命中即有迁移工作量。
3. 自定义 projection：加 `wire` 块保持 client-visible；纯 host 统计单元可省 `wire` 换 checkpoint-only。
4. `.credentials.yaml` 让 boot 迁移，不要手工改成三段结构（迁移器识别的是**精确的**旧布局）。
5. 发图工作流可依赖新管线自动缩放转格式，删除自带的预缩放逻辑。
