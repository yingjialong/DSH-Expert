# 0.1.1-rc.2 → 0.1.5-rc.2

这是跨多个发布系列的迁移，涉及产品功能、Host/Client 公共接口、Session 存储及插件合同，不能只替换版本号。下面是主要变化的有证据摘要，不是全部 3,225 次提交的逐条审核。

本次用户授权的本库升级已将源码镜像从 `d347e703908d0406b7a7ef80e3a0e594d86b2215` 快进至目标 `fb2c4b9e698e30edb738bca4cf0618587db7d203`，并将默认咨询基线改为 `0.1.5-rc.2`。不安装系统软件，不改外部项目依赖，不启动真实模型调用，不迁移用户数据。Cordis 独立镜像保持原版本；目标 DSH 的实际内核始终以其 vendor 源码为准。

## 集成方必须关注的断点

条件（八维坐标）：TS/JS 或进程外宿主 · Web/嵌入/SDK · 多 Session 与多进程 · 本地 JSONL 或自定义存储 · 复用公开 Agent/工具合同 · 不调用真实模型 · 平台差异分别验收 · 固定为上表两个发布 SHA。

1. **Host/Client 拆分**：旧 `packages/host/apiproxy` 和 `packages/client/runtime` 已删除，转为 `@Remote` Gateway、Session/Workspace/Settings controllers 和 Client store。原 ApiProxy 的导入、通信封装与 UI 状态 owner 都需逐项迁移；不是更换包名即可证明等价。
2. **异步 Agent 创建**：旧 `AgentLoop.create(...): Agent` 改为 `async create(...): Promise<Agent>`。创建成功、错误处理与后续使用都需 await。
3. **SessionHandle**：旧 `SessionPersistence.create(meta): Promise<void>` 及 service 上的 id-based 操作，改为 `create/open → SessionHandle`；handle 提供 `read/append/flush/close`。`append` 成功仅保证接纳、顺序与相应可见性，`flush` 才是 crash durability 屏障；write handle 的 `close` 完成耐久并释放 owner，必须等待。
4. **写 owner 与存储 provider**：JSONL 增加跨进程写租约；读 handle 可共存，不能概括为禁止另一进程读取 Session。POSIX 使用 native flock，Windows 有独立实现。旧 `session-persistence-sqlite` 包已删除，自定义 provider 必须适配新合同。
5. **日志 V3**：支持的历史日志经相邻迁移边生成新 artifact，保留原文件；升级后不支持旧版读取新日志。V2→V3 将系统提示词提升为 surface message，并重映射本地事件引用；旧 `code` preset 和 PTC 持久词汇也有精确转换。未知或不合规的旧 payload 可拒绝整次迁移，不能保证任意自定义事件兼容。
6. **Agent/Inbox 插件 API**：移除 ambient `ctx.agent`，显式传递 Agent；`Inbox` 为类型接口，插件经 `agent.inbox` 操作队列，不能再依赖原公开构造类及 `hasPending/claim`。
7. **提示词、UI 与进程接口**：persona 拆为 `personaPrefix/personaSuffix`；原 conversation Slot 改为 main 下 conversation key；普通 `SubprocessHandle` 不再有 pid，`SubprocessTerminalHandle` 仍有 pid。只改实际使用这些接缝的调用方。

**迁移推断（verified_inference）**：依赖 rc.2 完整 Host/Client 图或自定义持久化的产品应按接口迁移处理；仅使用标准 CLI 的用户主要面对 profile、默认工具和数据格式变化。实际迁移成本仍取决于调用方源码，本库不替代外部项目验收。

## 必须保留的限制

- 系统提示词的 in-history 路径要求模型明确声明能力；源码支持不保证远端模型实际缓存命中。
- 代理支持不等于“所有流量走代理”：目标 http-proxy 英文文档明确 OTLP telemetry 直连，执行模型代码的 code-runtime/workflow worker 不注入代理配置；也不自动读取 macOS 系统代理，不支持 SOCKS/PAC。
- 仅核对 npm 根包与关键 companion 的同版元数据/tarball URL，不把元数据存在当作完整依赖安装、native helper、构建或 boot 通过。
- 未执行真实模型调用、GUI/桌面启动或用户历史日志迁移。安全隔离和所有平台兼容性不在本次验证范围。
