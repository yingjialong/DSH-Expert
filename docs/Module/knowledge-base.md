# 模块：知识库（wiki/）

## 一、功能

存放**事实层**知识：DSH 是什么、怎么实现的、接口长什么样。以及知识库自身的四个治理文件。

事实层知识**会腐烂**（上游两天一个 rc），因此本模块的核心不是"存知识"，而是**"让腐烂的知识能被检测出来"**。

## 二、结构

| 文件/目录 | 职责 |
| --- | --- |
| `index.md` | 紧凑索引。每条只有：一行摘要 + 锚点 + status + freshness。回答时先读它，再挑 3-5 篇全文——这是不用 embedding 也能在规模下工作的关键 |
| `log.md` | 问答/学习/实测的时间线。兼作回归检测替代品 |
| `coverage.md` | 覆盖度地图。每个单元的掌握等级 L0-L4 + 最后核验时间。既是能力体检表也是学习待办 |
| `errors.md` | 错误本。答错的、死路、上游变更导致失效的、命名陷阱、文档与源码不符 |
| `open-questions.md` | 悬而未决。查了但没查到的 |
| `packages/` | 一个包组一页，映射上游 `packages/<group>` |
| `topics/` | 映射上游 `docs/<topic>` + Cordis + 版本变更 |
| `integration/` | 按八维坐标系组织的集成知识 |

## 三、页面契约

每页 frontmatter 七项必填：

```yaml
title / status / mastery / freshness / anchors / commit / verified_at / asked_by
```

四把标尺的取值见 `README.md` 2.4 节。三条关键规则：

1. **掌握等级封顶认知状态**：L1/L2 不得标 `fact`
2. **锚点必须真实存在**：没有锚点的页面无法被失效检测覆盖，等于埋雷
3. **不复制上游文档正文**：只写路由、踩坑、跨文档综合

## 四、防腐机制（本模块的核心）

```
/dsh-sync 拉取上游
  → git diff --name-only <旧SHA>..<新SHA>       得到变更文件集
  → rg 抽取 wiki/ 中所有锚点路径                得到锚点集
  → comm -12 取交集                             得到受影响条目
  → 这些条目 freshness := stale
  → 回答时若命中 stale：禁止直接引用，必须先复验
```

兜底：`verified_at` 超过 30 天的条目即使锚点未变也标 `stale`。

## 五、去项目化约束

集成类知识写成「**条件（八维坐标）→ 结论 → 锚点 → 认知状态**」，剥离项目名、私有路径、业务代码、业务逻辑。无法泛化的内容不入库。

附带效果：知识库里不会积累用户的私有项目信息，将来可整体公开而无需清洗。

## 六、规模控制

已知风险：LLM Wiki 模式下页面数量增长会显著推高每次问答的 token 成本（社区实践中 10 页 → 37 页时已明显）。

对策：
- `index.md` 只放一行摘要，**永远不全量加载知识库**
- 单页超过 ~400 行拆分
- `/dsh-wiki` 定期查重合并，同一事实不散落多处
