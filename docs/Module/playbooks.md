# 模块：方法库（playbooks/）

## 一、功能

存放**方法层**知识：遇到某类问题该怎么查、怎么选型、该问什么、哪些路走不通。

与 `wiki/`（事实层）的根本区别：

| | 事实层 `wiki/` | 方法层 `playbooks/` |
| --- | --- | --- |
| 内容 | DSH **是什么** | **怎么回答**关于 DSH 的问题 |
| 会腐烂吗 | 会（绑源码锚点，靠 diff 检测） | 基本不会 |
| 更新触发 | 上游 commit | 实战中方法被证伪 |

"遇到报错先去 `packages/<相关组>/README.md` 的 Known Limitations 章节看一眼"——这条方法一年后依然有效，而它指向的具体内容早就变了。

## 二、四本剧本

| 剧本 | 触发场景 | 核心价值 |
| --- | --- | --- |
| `新项目集成选型.md` | "我想把 DSH 集成进来" | 八维坐标 + 决策流程；**不绑定任何技术栈** |
| `报错诊断.md` | 粘来一段报错 | 三类错的分流（配置错/版本错/上游 bug）+ 报错文本精确定位法 |
| `插件开发.md` | "我要写个插件" | 四种插件形态的判定 + capability family 三件套 + 依赖纪律 |
| `版本升级评估.md` | "升级会炸什么" | 上千文件 diff 下的信号筛选法 + 按八维坐标说影响面 |

## 三、每本剧本的固定结构

1. **第 0 步：先分类**（几乎所有剧本都以分类开头，因为误判类型是最大的时间浪费）
2. **决策流程**（可执行，带命令）
3. **回答必须包含的几件事**（防止答得含糊）
4. **沉淀规则**（双门槛：主题准入 + 去项目化，见 `CLAUDE.md` 第 7 条）
5. **失败的方法**（走过的死路，与 `wiki/errors.md` 互补）

第 5 节是方法层特有的资产：**记录哪条查证路径浪费过时间**。

## 四、维护

剧本在实战中被修订：
- 某条方法失效 → 改，并在"失败的方法"表里补一行
- 出现新的高频问题类型 → 加新剧本

不做定期 lint（方法层不腐烂，没有失效检测的必要）。
